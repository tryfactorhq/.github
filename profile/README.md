# Factor

### Understand what your code change actually affects.

Factor analyzes software changes and builds an evidence-backed map of their impact across the system.

It helps engineering teams understand:

- **What changed** — the behavior and architecture being modified
- **What is affected** — services, dependencies, consumers, and execution paths
- **What evidence exists** — tests, callers, implementations, and existing validation
- **What still needs validation** — the risks and checks that matter before merge

Factor goes beyond the diff to trace how a change propagates through a real codebase.

## Why Factor?

A pull request tells you **what changed**.

It doesn't always tell you **what that change means for the system**.

Factor is built to close that gap.

> **Code tells you what changed. Factor helps you understand what it affects.**
